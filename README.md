# 레이저런 표적 · 카메라 인식 시스템 (v0.6)

태블릿 카메라로 종이 과녁을 비추면, 레이저가 **검정 원(7점 이상)** 에 맞을 때마다 초록불이 켜지고
5발을 다 맞히면 **CLEAR** 를 띄운 뒤 저절로 다시 시작합니다. 앱 설치 없이 태블릿 브라우저
(아이패드 Safari, 갤럭시탭 Chrome)에서 돌아갑니다.

```
태블릿 뒷면 카메라 ──▶ 종이 과녁        태블릿 화면 ──▶ 사수(10m)
   검정 원 자동 인식                       ● ● ● ○ ○   명중 3/5 · 7발 · 12.4초
   빨간 레이저 점 감지 → 명중/빗나감         5발 → CLEAR → 5초 뒤 자동 초기화
```

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `docs/` | 실제 홈페이지(GitHub Pages가 이 폴더를 그대로 보여 줍니다) |
| `docs/index.html` | 표적 앱 |
| `docs/target.html` | 과녁 만들기: A4 위에서 모서리를 끌어 크기를 정하고 실제 크기로 인쇄 |
| `docs/target-a4-*.pdf` | 바로 인쇄할 수 있는 과녁 2종(검정 59.5mm / 100mm) |
| `src/app.html`, `src/target.html` | 원본. 고친 뒤 `python3 build.py` 로 `docs/` 를 다시 만듭니다 |
| `target/` | 과녁 PDF 생성 스크립트 |
| `tests/` | 가상 카메라 영상으로 인식 성능을 재는 자동 테스트 |

## 1. 홈페이지(GitHub Pages)

저장소의 **Settings → Pages** 에서 *Deploy from a branch*, 브랜치 `main`, 폴더 `/docs` 를 고르면
`https://<아이디>.github.io/<저장소 이름>/` 에서 열립니다. 카메라는 https 주소에서만 켜지므로 이 주소로 써야 합니다.
아이패드는 공유 → **홈 화면에 추가** 하면 주소창 없는 전체 화면으로 쓸 수 있습니다.

사로마다 주소 뒤에 번호를 붙여 두면 편합니다: `…/index.html?lane=3` (설정의 사로 번호가 3으로 시작)
`&autostart=camera` 를 붙이면 시작 화면 없이 바로 카메라를 켭니다.

## 2. 과녁

- **과녁 만들기**(`target.html`): A4 미리보기에서 모서리 손잡이를 끌면 크기가 바뀌고, 검정 원 지름이 mm로 바로 보입니다.
  바깥 고리 수(1~10점 / 4~10점 / 검정만)를 고를 수 있고, 인쇄 창에서 *실제 크기(100%)·여백 없음* 으로 인쇄합니다.
  인쇄 뒤 아래쪽 50mm 눈금을 자로 재서 확인하세요.
- 검정 원 안의 선과 숫자는 일부러 회색으로 인쇄합니다. 카메라가 검정 원 전체를 한 덩어리로 보기 쉽습니다.
- 지금 쓰는 25m 종이 과녁도 그대로 인식됩니다.

## 3. 설치 · 사용 순서

1. 과녁 앞 0.7~1.5m, 레이저가 지나가는 길을 가리지 않는 **아래쪽**에 태블릿을 세웁니다. 뒷면 카메라는 과녁을,
   화면은 사수 쪽을 향합니다.
2. **시작하기**를 누르면 바로 표적 화면이 나오고, 과녁(검정 원)은 뒤에서 자동으로 찾습니다.
   카메라를 '허용'으로 정해 둔 기기는 시작 버튼 없이 바로 켜집니다.
3. 표적 화면: 왼쪽 2/3는 과녁(확대)과 이번 회차 탄착, 오른쪽 1/3은 사수 이름 · 초록불 · 사격 시간.
   5발 명중 시 사수 이름과 함께 CLEAR(걸린 시간·쏜 발수) → 5초 뒤 자동 초기화.
   시간은 첫 발에 시작하고, **제한 시간은 기본으로 없습니다**.
4. **확대**: 과녁 화면 오른쪽 아래 `− 1.0× +` 와 **과녁 맞춤**. 카메라가 확대를 지원하면 카메라 자체를 확대해서(글자 아래
   '카메라 확대') 과녁이 더 선명해지고, 아니면 화면만 키웁니다('화면 확대'). 과녁 맞춤은 과녁을 다시 찾아 화면에 꽉 맞춥니다.
   카메라 화질은 기본 1920×1080 입니다.
5. **정면 촬영**(기본 켬): 과녁을 정면에서 찍는다고 보고 검정 원을 동그라미로 맞춥니다. 비스듬히 찍을 때는 설정 모드 › 과녁 맞추기에서 끄세요.
   과녁 주변의 인쇄된 고리 선을 보고 진짜 과녁을 고르기 때문에, 화면에 검은 원(스피커·시계)이 있어도 헷갈리지 않습니다.
6. 조정할 것이 있으면 오른쪽 아래 **설정 모드**:
   과녁 맞추기(자동 인식·직접 조정) · 레이저 시험(감도, 신호 세기) · 사수 · 경기(사로 번호, **사수 명단**, 규칙) · 기록,
   잘 안 쓰는 카메라·해상도·입력 방식은 맨 아래 **고급 설정**에 접혀 있습니다. 설정 모드에서 쏜 것은 기록에 들어가지 않습니다.
7. **사수 명단**: 한 줄에 한 명씩 넣으면 표적 화면에 순서대로 나오고, CLEAR 뒤 다음 사람으로 넘어갑니다(‹ › 로 직접 바꿀 수도 있음).
   기록과 CSV에 이름이 같이 남습니다.

## 3-1. 인식이 이상할 때 (먼저 확인할 것)

- **놓침과 오인식은 뿌리가 같습니다: 깜빡임이 카메라 한 장보다 짧은 것.** 카메라는 1초에 60장을 찍지만
  한 장마다 셔터가 열려 있는 시간은 그중 일부입니다. 아주 짧은 깜빡임은
  - 셔터가 닫힌 틈에 지나가면 **카메라에 아예 안 찍히고**(어떤 소프트웨어로도 되살릴 수 없음),
  - 반쯤 걸치면 약하게 찍힙니다. 이걸 잡으려고 문턱을 낮추면 조명 깜빡임·잡음까지 잡혀 **쏘지 않았는데 맞았다고** 나옵니다.

  **해결: 총의 깜빡임을 0.1초(100ms) 정도로 늘리고**, 고급 설정 › 레이저 방식을 **깜빡 0.1초 이상** 으로 바꾸세요.
  그러면 한 발이 5~6장에 찍혀서 놓칠 수가 없고, 두 장 이상 찍힌 빛만 인정하니 오인식도 거의 사라집니다(0.5초 미만이면 됩니다).
- **놓친 프레임**: 설정 › 레이저 시험 아래 '프레임' 줄과 오른쪽 위 칩에 카메라가 보낸 장수, 앱이 본 장수, 놓친 비율이 나옵니다.
  5%를 넘으면 노랗게 바뀝니다. v0.6부터 지원되는 브라우저(아이패드는 iPadOS 18 이상의 Safari, 크롬)에서는
  화면 표시와 상관없이 **모든 프레임을 별도 일꾼(Web Worker)에서 읽습니다**. 안 되는 기기에서는 예전 방식으로 저절로 돌아갑니다.
- 종이는 **네 귀퉁이를 다 고정**하세요. 위 한 곳만 꽂으면 바람에 살짝 흔들립니다.
- 설정 모드 맨 아래 **진단** 칸: 감지된 자리를 과녁 그림에 번호로 찍고, 그 순간과 바로 전의 작은 사진, 판정 이유,
  앞뒤 프레임을 놓쳤는지가 쌓입니다. 쏘지 않았는데 잡히거나 맞혔는데 안 잡히면 이 칸을 캡처해서 보내 주세요.
- **진단 녹화**: 같은 칸의 '진단 녹화 12초'를 누르고 몇 발 쏘면, 카메라 영상(모든 프레임)과 앱이 프레임마다 본 기록이
  파일 두 개로 남습니다. '녹화 저장 · 보내기' → 파일에 저장 → 저장소의 `diag/` 폴더에 올리면, 컴퓨터에서 같은 판정 코드로
  한 장씩 다시 돌려 어디서 놓쳤는지 확인할 수 있습니다(파일에 학생 이름은 들어가지 않습니다).
- 판정 규칙: 깜빡이는 빛만 셉니다(0.5초 넘게 켜져 있는 빛은 반사·조명으로 보고 무시). 주변이 함께 어두워지면
  움직임으로, 바로 전 장면에도 있던 빛이면 오래된 빛으로 보고 거릅니다. 화면 전체 색·밝기 변화와 조명 깜빡임 줄무늬는 빼고 봅니다.
  계속 켜지는 레이저라면 고급 설정 › 레이저 방식을 바꾸세요.

## 4. 야외에서 잘 잡히게 하려면

햇빛은 레이저 점보다 훨씬 밝습니다. 직사광선 아래 검정 원에서 1~5mW 레이저 점은 빨강 값을 겨우 +10~40 올립니다.
그래서 소프트웨어만큼 **현장 준비**가 중요합니다. 효과가 큰 순서:

1. **과녁에 그늘 만들기** — 과녁 둘레에 깊이 20~30cm 정도의 차양(상자)을 대면 주변 빛이 5~10배 줄어 인식이 확 좋아집니다.
   나뭇잎 그림자가 과녁 위에서 흔들리지 않는 자리가 좋습니다.
2. **레이저 깜빡임을 0.1초쯤으로** — 카메라는 1초에 30장을 찍습니다. 0.1초면 2~3장에 걸쳐 찍혀서
   '두 장 연속 같은 자리' 확인으로 약한 빛도 안전하게 잡습니다. 아주 짧게 깜빡이면 사진과 사진 사이로 지나갈 수 있어요.
3. **10m에서 점이 작게 모이도록 레이저 렌즈 초점 맞추기** — 같은 세기라도 점이 작을수록 훨씬 밝습니다.
4. 감도는 기본 6을 권합니다. 8 이상은 나뭇잎 그림자가 과녁 위에서 움직일 때 드물게 잘못 잡힙니다.

레이저는 사람 눈을 향하지 않게 해 주세요. 더 센 레이저보다 그늘·초점·깜빡임 길이가 훨씬 안전하고 효과도 큽니다.

## 5. 판정 방식

- **과녁 찾기**: 화면에서 가장 과녁다운 검정 원을 찾아 타원으로 맞춥니다(비스듬해도 됨). 1.2초마다 과녁 위치를 다시 확인해서
  태블릿이 살짝 밀려도 따라갑니다.
- **레이저 찾기** (두 단계):
  - *또렷한 빛*: 빨강이 크게, 초록·파랑보다 훨씬 많이 밝아진 작은 점. 화면 전체에서 찾고 흰 부분의 빗나감도 잡습니다.
  - *약한 빛*(햇빛 아래): 검정 원 안에서만, 3×3 픽셀의 '빨강 초과분'을 그 픽셀의 평소 잡음과 비교합니다.
    잡음보다 충분히 크면 바로, 조금 약하면 **두 장 연속 같은 자리**에 보일 때 인정합니다.
    주변까지 함께 밝아진 것(그림자 경계)은 레이저가 아니라고 보고 버립니다.
  - 화면 전체 밝기 변화(구름, 자동 노출)는 빼고 보고, 크게 움직이는 것(사람, 손)이 있으면 그 순간 0.3초는 무시합니다.
- **한 번 당긴 방아쇠 = 한 발**: 빛이 여러 장에 걸쳐도 한 번만 셉니다.
- **프레임 읽기**: 카메라 프레임을 Web Worker 가 `MediaStreamTrackProcessor` 로 하나도 빠짐없이 받아 판정까지 하고,
  화면(메인 스레드)은 결과만 받습니다. 시작할 때 일꾼이 받은 그림이 화면의 그림과 같은지(크기·방향) 확인하고,
  다르거나 멈추면 예전 방식(`requestVideoFrameCallback`)으로 돌아갑니다. 프레임마다 시각을 보고 빠진 장수를 셉니다.
- **점수**: 검정 원 테두리를 1로 놓은 거리 ρ 로 계산합니다(고리 간격 = 검정 반지름의 1/4). 명중 = ρ ≤ 1.

## 6. 시험 결과 (가상 카메라 영상)

태블릿 카메라를 흉내 낸 영상을 크롬에 *웹캠으로* 넣고 앱을 그대로 돌린 결과입니다(기본 감도 6).

| 장면 | 감지 | 판정 일치 | 오탐 |
|---|---|---|---|
| 실내, 인쇄 과녁 + 방해 요소(노출 급변·사람·흔들림·초록 빛) | 17/18 | 17/17 | 0 |
| 교실 재현(조명 깜빡임·화이트밸런스 변화·종이 흔들림·초점 흔들림, 대부분 1프레임 깜빡임) | 18/19 | 전부 일치 | 0 |
| 정면, 작은 25m 과녁 + 검은 둥근 물체(스피커) | 9/9 | 9/9 | 0 |
| 실내, 지금 쓰는 25m 과녁(어두운 방·심한 기울기) | 11/11 | 11/11 | 0 |
| **야외 직사광선**(점이 빨강을 +10~37만 올림, 구름·바람·나뭇잎 그림자) | 13/14 (명중 11/11, 흰 부분도 잡음) | 13/13 | 0 |
| **야외 그늘 차양** | 15/15 | 15/15 | 0 |
| 야외 40초, 쏘지 않음(구름·강풍·검정 원 위 나뭇잎 그림자) | – | – | 0 (감도 8: 3~4) |

- 이전 버전은 직사광선에서 0/14, 그늘에서 5/15였습니다.
- 놓친 것은 모두 햇빛에 흰 종이가 완전히 하얗게(255) 날아간 곳의 빗나감입니다. 카메라로는 원래 볼 수 없습니다.
- v0.6 결과는 '모든 프레임 읽기'(크롬: 페이지에서 읽어 일꾼에 넘김)로 잰 것입니다. 예전 방식은 `READER=main node tests/e2e.mjs …`.
- 다시 돌리기: `python3 tests/make_outdoor.py out_sun` → `node tests/e2e.mjs out_sun`
  (실내: `tests/make_video.py scene_a4`, 교실: `tests/make_room.py`, 쏘지 않는 시험: `out_soak`, 감도 지정: `node tests/e2e.mjs out_soak 8`)
- 그 밖의 도구: `node tests/bench.mjs front_room 400`(한 장 처리 시간), `node tests/soakdet.mjs out_soak 8`(시간과 상관없이 같은 결과가 나오는 오인식 세기),
  `node tests/rec.mjs`(진단 녹화·진단 칸 확인), `python3 tests/replay.py diag/<녹화>.mp4`(태블릿 녹화 분석: 영상 속 깜빡임 전부 ↔ 앱이 센 것)

## 7. 다른 시스템과 연동

모든 이벤트는 같은 페이지의 `lasertarget` 이벤트 · `BroadcastChannel('laser-target')` · (iframe일 때) 부모 창
`postMessage` 로 나갑니다.

```js
{ source: 'laser-target', version: 1, type: 'shot', lane: 1, at: 1763380000000, input: 'camera',
  shot:   { hit: true, score: 8, rho: 0.62, x: 0.31, y: -0.54, frames: 2 },   // x,y: 검정 반지름 = 1
  series: { hits: 3, shots: 4, need: 5, elapsedMs: 12400 } }
// type: 'start' | 'shot' | 'clear' | 'timeout' | 'reset' | 'test-shot' | 'state'
```

명령: `{ target: 'laser-target', cmd: 'reset' | 'config' | 'state' | 'shooter', settings?, name? }` (`shooter` 는 지금 사수 이름을 바깥에서 정함). 시험용 `LaserTarget.simulateShot(x, y)`.

SDSMP(claude.ai 아티팩트)와의 연결은 아티팩트 보안 구조 때문에 별도 설계가 필요합니다(대화 기록 참고).
